## Why This Matters: The Retina Gap

When Apple introduced the iPhone 4 Retina display in 2010, the Device Pixel Ratio jumped from 1 to 2. This meant the screen had 4 times as many physical pixels in the same physical area.

The web was not ready.

Every existing website suddenly looked soft and blurry on the new display — not because the sites were broken, but because they were serving 1× images that the 2× screen was forced to upscale. Text (rendered by the browser's vector engine) looked crisp. Images looked like 1990s JPEGs.

Fifteen years later, almost all flagship phones operate at DPR 3 (iPhone 16 Pro) or even DPR 4 (some Samsung devices). Laptop Retina displays are standard on premium hardware. If your website serves one-size-fits-all images, those images look blurry on the majority of your users' screens.

<CalloutBox type="info" title="The Visual Impact">
  The difference between a 1× image on a 2× screen and a properly served 2× image is stark — comparable to the difference between a standard-definition and high-definition video. Users may not consciously notice, but their perception of your brand's quality is directly affected.
</CalloutBox>

## Part 1: The srcset Attribute — Density Descriptors

The simplest way to handle Retina images for fixed-size elements is the **density descriptor** form of srcset.

### Basic syntax

```html
<img
  src="logo.png"
  srcset="logo.png 1x,
          logo-2x.png 2x,
          logo-3x.png 3x"
  alt="Company Logo"
  width="200"
  height="60"
/>
```

**What this does:**
- On a standard (DPR 1) screen → downloads `logo.png`
- On a Retina (DPR 2) screen → downloads `logo-2x.png`
- On a 3× screen (iPhone Pro) → downloads `logo-3x.png`

The `src` attribute is the fallback for browsers that don't support srcset (very rare now).

### When to use this form

Use density descriptors for images that are always displayed at the same CSS size — logos, avatars, icons, and fixed UI elements. If the image is `width: 200px` in CSS, export it at 200px, 400px, and 600px, and label them 1x, 2x, 3x.

## Part 2: srcset + sizes — Width Descriptors for Responsive Images

For images that change size at different viewport widths (the majority of article images, hero photos, and card images), use **width descriptors** combined with the `sizes` attribute.

### Why density descriptors aren't enough for fluid layouts

A hero image might be 1440px wide on desktop but only 375px wide on mobile. If you only provide 1× and 2× variants, the browser has to guess which to use based solely on DPR — it doesn't know the image's rendered width.

Width descriptors give the browser exact file widths, and `sizes` tells it the rendered display widths. The browser can then pick the perfect file.

### Syntax with width descriptors

```html
<img
  src="hero-800.webp"
  srcset="hero-400.webp 400w,
          hero-800.webp 800w,
          hero-1200.webp 1200w,
          hero-1600.webp 1600w,
          hero-2400.webp 2400w"
  sizes="(max-width: 640px) 100vw,
         (max-width: 1024px) 80vw,
         1200px"
  alt="Hero banner"
  width="1200"
  height="600"
/>
```

**How the browser uses this:**

1. Reads the `sizes` attribute to find the applicable condition:
   - On a 375px viewport → `100vw` → image will display at 375px
   - On a 768px viewport → `80vw` → image will display at 614px
   - On a 1440px viewport → `1200px` (fixed, not the full viewport)

2. Multiplies by the device DPR:
   - 375px display × DPR 3 = 1125 device pixels needed

3. Picks the smallest srcset candidate ≥ 1125w:
   - Selects `hero-1200.webp` (1200w)

The browser downloads the minimum file that looks sharp on that specific device. This saves significant bandwidth on small screens and ensures sharpness on large high-DPI displays.

### Writing effective sizes values

```html
<!-- Full-width on mobile, 2-column grid on desktop -->
sizes="(max-width: 768px) 100vw, 50vw"

<!-- Full-width always, but capped at 1200px container -->
sizes="(max-width: 1200px) 100vw, 1200px"

<!-- Thumbnail that's always 200px wide -->
sizes="200px"

<!-- Blog article image: full-width mobile, centered column on desktop -->
sizes="(max-width: 640px) calc(100vw - 32px),
       (max-width: 1024px) calc(100vw - 128px),
       720px"
```

<CalloutBox type="tip" title="Always Include width and height Attributes">
  Adding `width` and `height` attributes to `<img>` tags (in CSS pixels) lets the browser reserve space before the image loads. This prevents Cumulative Layout Shift (CLS) — the jarring reflow where content jumps down when images load. This is a Core Web Vitals metric that directly affects Google search rankings.
</CalloutBox>

## Part 3: The picture Element — Art Direction and Format Fallbacks

The `<picture>` element is a container that gives you explicit control over which image file the browser downloads, using media queries or format detection.

### Use case 1: Format fallbacks (WebP with JPEG fallback)

```html
<picture>
  <source
    type="image/avif"
    srcset="photo-800.avif 800w, photo-1600.avif 1600w"
    sizes="(max-width: 768px) 100vw, 800px"
  />
  <source
    type="image/webp"
    srcset="photo-800.webp 800w, photo-1600.webp 1600w"
    sizes="(max-width: 768px) 100vw, 800px"
  />
  <img
    src="photo-800.jpg"
    srcset="photo-800.jpg 800w, photo-1600.jpg 1600w"
    sizes="(max-width: 768px) 100vw, 800px"
    alt="Descriptive alt text"
    width="800"
    height="600"
    loading="lazy"
  />
</picture>
```

The browser picks the first `<source>` whose type it supports. AVIF-capable browsers get the smallest files. WebP-capable browsers (96%+ of users) get WebP. Everyone else gets JPEG.

### Use case 2: Art direction — different crops on different screens

```html
<picture>
  <!-- Mobile: portrait crop, subject-focused -->
  <source
    media="(max-width: 640px)"
    srcset="hero-mobile-375.webp 375w, hero-mobile-750.webp 750w"
    sizes="100vw"
  />
  <!-- Desktop: wide landscape crop -->
  <source
    media="(min-width: 641px)"
    srcset="hero-desktop-1200.webp 1200w, hero-desktop-2400.webp 2400w"
    sizes="(max-width: 1440px) 100vw, 1440px"
  />
  <img src="hero-desktop-1200.webp" alt="Hero" width="1200" height="500" />
</picture>
```

This is "art direction" — serving a completely different composition (not just a different resolution) based on the viewport.

## Part 4: CSS Background Images for High-Density Screens

For background images set via CSS, srcset doesn't apply. You have two options:

### Option 1: image-set()

```css
.hero {
  background-image: image-set(
    url("/images/hero-1x.webp") 1x,
    url("/images/hero-2x.webp") 2x,
    url("/images/hero-3x.webp") 3x
  );
  background-size: cover;
}
```

Browser support: excellent (Chrome, Firefox, Safari all support it, with or without vendor prefix).

### Option 2: Media queries with resolution targeting

```css
.logo-bg {
  background-image: url('/logo-1x.png');
}

@media
  (-webkit-min-device-pixel-ratio: 2),
  (min-resolution: 192dpi),
  (min-resolution: 2dppx) {
  .logo-bg {
    background-image: url('/logo-2x.png');
    background-size: 200px 60px; /* Must match CSS display size */
  }
}

@media
  (-webkit-min-device-pixel-ratio: 3),
  (min-resolution: 288dpi),
  (min-resolution: 3dppx) {
  .logo-bg {
    background-image: url('/logo-3x.png');
    background-size: 200px 60px;
  }
}
```

<CalloutBox type="warning" title="Background-size Must Match CSS Display Size">
  When you serve a 2× background image (400×120px for a 200×60px display area), you must also set background-size: 200px 60px (the CSS display size) — otherwise the image renders at its full physical dimensions (twice as large as expected).
</CalloutBox>

## Part 5: Framework Solutions

### Next.js Image Component

Next.js has a built-in `<Image>` component that handles srcset, lazy loading, format conversion, and size optimization automatically:

```jsx
import Image from 'next/image';

export default function HeroSection() {
  return (
    <Image
      src="/hero.jpg"
      alt="Hero image"
      width={1200}
      height={600}
      priority          // preload above-the-fold images
      sizes="(max-width: 768px) 100vw, 1200px"
      quality={85}      // 85 is optimal for web (vs. default 75)
    />
  );
}
```

Next.js automatically:
- Converts to WebP (or AVIF)
- Generates multiple sizes for srcset
- Adds width/height to prevent CLS
- Lazy loads below-the-fold images

### Astro Image Component

```astro
---
import { Image } from 'astro:assets';
import heroImage from '../assets/hero.jpg';
---

<Image
  src={heroImage}
  alt="Hero image"
  widths={[400, 800, 1200, 1600]}
  sizes="(max-width: 640px) 100vw, 1200px"
  format="webp"
  quality={85}
/>
```

Astro processes the image at build time — no runtime overhead.

## Part 6: Performance Considerations

Serving high-quality Retina images responsibly requires balancing quality against file size.

| Strategy | Impact |
|---|---|
| Use WebP over JPEG | 25–35% smaller for same quality |
| Use AVIF over WebP | 30–50% smaller (slower to encode) |
| Lazy load off-screen images (`loading="lazy"`) | Reduces initial page load time significantly |
| Preload critical above-fold images | Reduces Largest Contentful Paint (LCP) |
| Use CDN-level image optimization | Eliminates manual srcset variant creation |
| Compress images at quality 80–85 | Minimal visible difference, significant size reduction |

<CalloutBox type="tip" title="Quick Test: Is Your Image Correctly Served?">
  1. Open Chrome DevTools → Network tab
  2. Filter by "Img"
  3. Hard-reload the page (Cmd/Ctrl+Shift+R)
  4. Click each image request — check the "Name" column
  5. Verify that 2× screen → 2× image file is being downloaded
  
  Alternatively: DevTools → Sources → right-click any image → "Open in new tab" and check the URL filename.
</CalloutBox>

## Key Takeaways

- Every image on a modern website needs srcset — without it, Retina screens get blurry images.
- **Density descriptors** (1x/2x/3x) for fixed-size elements. **Width descriptors** (400w/800w) + `sizes` for responsive fluid images.
- The `<picture>` element enables format fallbacks (AVIF → WebP → JPEG) and art direction (different compositions per screen size).
- CSS background images use `image-set()` or resolution media queries.
- Next.js and Astro handle most of this automatically — use their `<Image>` components for production apps.
- Always include `width` and `height` attributes on `<img>` to prevent layout shift (CLS).
